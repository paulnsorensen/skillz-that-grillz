# gh-563: a large editable set gets a longer reflection timeout, a prose fallback or a warning, and an idle stop trigger

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/563

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a model call sends a prompt THE SYSTEM SHALL add 1 second per `PROMPT_CHARS_PER_SECOND` prompt characters to its per-call timeout, and the remaining search time SHALL still cap it. |  |
| AC-2 | test | WHEN a reflection call times out or answers THE SYSTEM SHALL record `prompt_chars` on its reflection outcome. |  |
| AC-3 | test | WHEN `--edit` is omitted and the `prose+cli` editable text exceeds `REFLECTION_TEXT_LIMIT` characters THE SYSTEM SHALL plan `prose` and write one stderr note that names the limit. |  |
| AC-4 | test | WHEN the planned editable text still exceeds `REFLECTION_TEXT_LIMIT` characters THE SYSTEM SHALL add `reflection_warning` to the `budget-unapproved` stop and write it to stderr. |  |
| AC-5 | test | WHEN the engine stops because it added no new evaluation for the skip limit THE SYSTEM SHALL record `search.stop_trigger` `idle`, not `stall`. |  |
| AC-6 | process | `skills/skillz/references/experiments.md` documents the scaled timeout, the size fallback, the warning, `prompt_chars`, and the `idle` trigger. | review of the gh-563 pull request |
