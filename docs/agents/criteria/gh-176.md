# gh-176: the Read tool cannot read host files outside the workspace

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/176

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN the runner starts Claude Code, THE SYSTEM SHALL write `permissions.blockReadsOutsideWorkingDirectories: true` in the settings it passes. |  |
| AC-2 | test | WHEN the preflight Read step reads a host file outside the workspace and the read returns content, THE SYSTEM SHALL stop with `preflight-leak` before any search call. |  |
| AC-3 | test | WHEN the preflight Read step gets a tool error for the host file and for the sealed file, THE SYSTEM SHALL pass the Read step. |  |
| AC-4 | test | WHEN the preflight Read step refuses the host file, THE SYSTEM SHALL record `read_tool: {host_file: /etc/hosts, result: refused}` in the preflight evidence. |  |
| AC-5 | test | WHEN a reader opens `experiment-harness.md` or ADR-006, THE SYSTEM SHALL state the setting, the probe targets, and why Read stays in `TOOLS`. |  |
| AC-6 | process | WHEN the preflight runs live on Claude Code, the live check SHALL show the Read tool refuse the sealed file and `/etc/hosts`. | Live: one preflight call on Claude Code 2.1.310, Linux 7.0.0-38, model `claude-sonnet-4-6`, on 2026-10-26, with the `read-tool-outside-workspace-v2` probe. The Read tool got a tool error for the sealed file and for `/etc/hosts`; the error names `permissions.blockReadsOutsideWorkingDirectories`. The preflight passed with `read_tool: {host_file: /etc/hosts, result: refused}`, `isolation: passed`, and `network: denied`. The v3 symlink and control steps have no live record yet. |
| AC-7 | test | WHEN the preflight Read step reads the workspace symlink to the sealed file and the read returns the sealed token, or no Read call answers for the symlink, THE SYSTEM SHALL stop with `preflight-leak`. |  |
| AC-8 | test | WHEN the preflight Read step cannot return the workspace control file, THE SYSTEM SHALL stop with `preflight-leak`, because the probe has no positive control. |  |
| AC-9 | test | WHEN the host has no `/etc/hosts`, THE SYSTEM SHALL stop with `host-not-ready` before any model call. |  |
