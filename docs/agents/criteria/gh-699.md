# gh-699: a contract companion can be a sibling directory

Source: gh-699 (GitHub issue)

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a contract names the companion `../<name>` THE SYSTEM SHALL accept it and `validate` SHALL report no `contract-surface` finding |  |
| AC-2 | test | WHEN the Claude task role stages a sibling companion THE SYSTEM SHALL stage its files read-only at `.claude/skills/<name>` |  |
| AC-3 | test | WHEN a sibling file changes THE SYSTEM SHALL change the candidate identity |  |
| AC-4 | test | WHEN a companion is an absolute path, has a hidden part, has `..` anywhere but as the first of two parts, is deeper than `../<name>`, or stages to the same `<name>` as another companion THE SYSTEM SHALL stop with `contract-surface` |  |
| AC-5 | test | WHEN a sibling is missing, is not a directory, is a symlink, or has the name of the target directory THE SYSTEM SHALL stop with `contract-surface` |  |
| AC-6 | process | WHEN the docs change THE SYSTEM SHALL describe the `../<name>` companion and its refusals | review of `eval-formats.md` and `experiments.md` |
