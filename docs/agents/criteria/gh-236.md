# gh-236: deterministic proposal leakage check (W3.1)

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/236

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a proposal adds a verbatim 8-word span from a train case request THE SYSTEM SHALL return `Leak(rule="request-span")`. |  |
| AC-2 | test | WHEN a proposal adds an `expected` string of 20 or more characters THE SYSTEM SHALL return `Leak(rule="expected-answer")`. |  |
| AC-3 | test | WHEN a proposal adds a case identifier or a fixture file name THE SYSTEM SHALL return `case-id` or `fixture-name`. |  |
| AC-4 | test | WHEN the seed already contains the same span THE SYSTEM SHALL return `None`. |  |
| AC-5 | test | WHEN a test seeds a distinctive string in a holdout case only THE SYSTEM SHALL return `None` for a proposal that contains it (holdout is not in the denylist). |  |
| AC-6 | test | WHEN a `Leak` is returned THE SYSTEM SHALL not include the matched text in any field or in `repr`. |  |
| AC-7 | test | WHEN a 7-word overlap or a common short phrase is added THE SYSTEM SHALL return `None`. |  |
