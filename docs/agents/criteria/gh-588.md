# gh-588: a task run raises its call cap, sees a repeats table, and records its unspent reserve

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/588 (items 2-4; spec autoimprove-seed-signals C3)

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a task run passes `--approve-budget N` with 200 < N <= 1000 THE SYSTEM SHALL size the search against N calls and a seconds cap of at most 28800 that scales with N, refuse an N above 1000 with `budget-cap-exceeded`, and keep the journey ceiling for a run with a journey case. |  |
| AC-2 | test | WHEN a `budget-unapproved` stop has no `--repeats` THE SYSTEM SHALL add `repeats_table` with a row for each of repeats 1, 2, and 3 from the real plan, where a row whose plan stops shows `fits: false` and that stop's text, and repeat the table in the stop text. |  |
| AC-3 | test | WHEN a run ends THE SYSTEM SHALL record `budget.unspent` with the reserve `calls` and `seconds` that the search did not spend, and show it in `summary` and `export`. |  |
| AC-4 | test | WHEN a plan does not fit the call cap THE SYSTEM SHALL name the smallest approved number up to 1000 that fits. |  |
