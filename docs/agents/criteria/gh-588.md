# gh-588: a task run raises its call cap, sees a repeats table, and records its unspent reserve

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/588 (items 2-4; spec autoimprove-seed-signals C3)

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a task plan has approval `--approve-budget N` with 200 < N <= 1000 THE SYSTEM SHALL size the approved plan against N calls. The seconds cap SHALL scale with N up to 28800. It SHALL refuse N above 1000 with `budget-cap-exceeded` and retain the journey ceiling for plans with journey cases. |  |
| AC-2 | test | WHEN a search `budget-unapproved` stop has no `--repeats` THE SYSTEM SHALL add `repeats_table` with one row for each of repeats 1, 2, and 3 from the real search plan. A row whose plan stops SHALL show `fits: false` and its stop text. The stop text SHALL repeat the table. |  |
| AC-3 | test | WHEN a search completes THE SYSTEM SHALL record `budget.unspent` with the reserve `calls` and `seconds` that the search did not spend, and show it in `summary` and `export`. |  |
| AC-4 | test | WHEN a plan does not fit the call cap THE SYSTEM SHALL name the smallest approved number up to 1000 that fits. |  |
