# gh-651: a regression case shows whether it reproduces the field failure on the seed

Source: gh-651 (GitHub issue; decisions D1 to D3, F1, and F2)

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a case sets `regression: true` with `source: session` THE SYSTEM SHALL accept it; WHEN `regression` is not a boolean, or is true with another source or on a pending `trigger` or `near-miss` draft case, THE SYSTEM SHALL stop with `cases-invalid` for a draft, or with the journeys-file error, and name the case |  |
| AC-2 | test | WHEN `regression` is omitted or false THE SYSTEM SHALL produce the same case data and case hash as before the field existed |  |
| AC-3 | test | WHEN the headroom pass finishes THE SYSTEM SHALL record, for each train or validation regression case, `headroom.reproduction.<case_id>` with the split, the seed score of each repeat, `reproduces`, `solvable: unknown`, and the unmet criteria, and SHALL record `reproduces: null` with a reason for a case with no scored outcome |  |
| AC-4 | test | WHEN the headroom pass runs THE SYSTEM SHALL score each holdout regression case once with the seed under the arm `reproduce` with `holdout=True`, before the too-easy decision; no search, gate, claim, or baseline computation SHALL read a `reproduce` outcome; a resume SHALL NOT score it again; WHEN a `reproduce` evaluation fails THE SYSTEM SHALL stop with `holdout-faulted` before it records `headroom`, and a resume SHALL score only the failed cases |  |
| AC-5 | test | WHEN the seed scores a regression case 1.0 on every scored repeat (a floor case; amended by gh-663) THE SYSTEM SHALL keep that case out of its family mean, SHALL NOT stop a family that has only such floor cases with `cases-too-easy`, and SHALL keep the case in `headroom.reproduction` |  |
| AC-6 | test | WHEN the plan builds the budget estimate THE SYSTEM SHALL add the call cost of each holdout regression case to the approved total and show it as `estimate.reproduce.calls`; WHEN there is none, THE SYSTEM SHALL leave the estimate as it was |  |
| AC-7 | test | WHEN a run stops with `cases-too-easy` THE SYSTEM SHALL include `headroom.reproduction` in the `baseline.headroom` data of the stop |  |
| AC-9 | test | WHEN a run returns its summary THE SYSTEM SHALL include the recorded `headroom` block, and WHEN a regression case is in holdout THE SYSTEM SHALL keep only the level of each unmet criterion, with no judge reason |  |
| AC-10 | test | WHEN the gate pairs the holdout repeats THE SYSTEM SHALL mark a case as a negative flip when the baseline scores 1.0 on every scored repeat and the winner repeat mean is below 0.5, and SHALL list the flips sorted by case id; WHEN such a case does not flip but its winner mean, with each missing repeat of the planned repeats taken as 0, is below 0.5, THE SYSTEM SHALL list it as unscored, sorted by case id |  |
| AC-11 | test | WHEN a holdout verdict would be `promote` or `promote-cheaper` and a negative flip or an unscored protected case exists THE SYSTEM SHALL return `inconclusive` with reason `negative-flip:<case_id>` for each flip, then `unscored-protected:<case_id>` for each unscored case; THE SYSTEM SHALL leave any other verdict unchanged, and a family breach SHALL still force `reject` |  |
| AC-12 | test | WHEN a run gates a winner that loses a case that the baseline passed on every repeat, while the mean delta would promote, or whose evaluations of that case all fail, THE SYSTEM SHALL record `inconclusive` with `negative-flip:<case_id>` or `unscored-protected:<case_id>`, and the improvement claim SHALL be `inconclusive` with `apply` false |  |
| AC-8 | process | WHEN the docs change THE SYSTEM SHALL describe the `regression` field, the fail-to-pass rule, the floor case as pass-to-pass, `solvable: unknown`, and the cost of the `reproduce` arm | review of `experiments.md`, `eval-formats.md`, and ADR-018 |
| AC-13 | test | WHEN the scaffold journey gate reads a Claude or a Codex trace THE SYSTEM SHALL turn each event into the same step shape (`tool`, `input`, `text`), so that one `RECEIPTS` list passes on both traces of one flow; an unknown event SHALL give no step |  |
| AC-14 | test | WHEN a receipt has no matching step THE SYSTEM SHALL print score 0 with `receipt-missing:<name>` for the first missing receipt only |  |
| AC-15 | test | WHEN receipts appear out of order THE SYSTEM SHALL fail the first one that has no later match; WHEN other steps sit between receipts THE SYSTEM SHALL accept them; WHEN a receipt appears only after the first `TERMINAL` step THE SYSTEM SHALL NOT count it |  |
| AC-16 | test | WHEN a matcher gives `tool`, `input`, or `text` THE SYSTEM SHALL require every given field to match one step, and the gate run as `python3 -I -c` with an author-edited `RECEIPTS` list SHALL enforce it |  |
| AC-17 | test | WHEN `RECEIPTS` is empty and `TERMINAL` is None THE SYSTEM SHALL print the same result as before for every trace |  |
| AC-18 | process | WHEN the docs and the scaffold rubric change THE SYSTEM SHALL tell the judge to grade the output files against each criterion, let `must` and `must_not` name an artifact property, and document `RECEIPTS`, `TERMINAL`, the in-order rule, and the terminal bound | review of `experiments.md` and the `RUBRIC` text |
