# gh-312: a contract check returns one typed result, and checks of different candidates run at the same time

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/312

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a Claude, Codex, or command transport checks a candidate THE SYSTEM SHALL return one `CheckResult` with `passed`, `reason`, and `kind`, and the `Checker` protocol SHALL have no `rejection` attribute. |  |
| AC-2 | test | WHEN `CheckMemo.check` checks a candidate THE SYSTEM SHALL store the returned `CheckResult` and SHALL read no transport attribute after the call. |  |
| AC-3 | test | WHEN two threads check two different candidate identities at the same time THE SYSTEM SHALL run both checks concurrently. |  |
| AC-4 | test | WHEN two threads check the same candidate identity at the same time THE SYSTEM SHALL run the check for that identity in one memo call and give both threads the same final `CheckResult`. The timeout part of this criterion belongs to gh-287. |  |
| AC-15 | process | ADR-013 in `docs/agents/decisions/skillz-autoimprove.md` records the typed value and the per-identity lock. | review of the gh-312 pull request: ADR-013 amendment |
