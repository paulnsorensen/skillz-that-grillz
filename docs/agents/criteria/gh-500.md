# gh-500: repeat validation runs and gate the incumbent with the 2-SE rule

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/500

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a candidate is scored on a validation case, THE SYSTEM SHALL record two outcomes with `repeat` 0 and 1 from two provider calls, AND GEPA SHALL receive their mean. |  |
| AC-5 | test | WHEN the run plans and spends the budget, THE SYSTEM SHALL count `VALIDATION_REPEATS` runs per validation case in the plan, the admission check, `search_allowance` and its overshoot, and the `search_ceiling` seed term, AND the wrapper SHALL debit 0 for a reused pair, AND the physical search task runs SHALL NOT exceed the planned search share. |  |
| AC-6 | test | WHEN GEPA selects a parent, THE SYSTEM SHALL pass per-case mean scores and SHALL NOT filter candidates by the 2-SE rule. |  |
| AC-7 | test | WHEN the search stops, THE SYSTEM SHALL write `search.stop_trigger` with the limit that fired, tested once for each value: `metric-count`, `call-share`, `stall`, `search-deadline`, `deadline`, and `call-cap`. |  |
| AC-8 | test | WHEN a run that recorded `validation_policy.repeats` 2 is resumed by a build with another value, or a run with no `validation_policy` is resumed, THE SYSTEM SHALL refuse with a coded error before the engine-hash check; WHEN a completed pre-change run is exported, THE SYSTEM SHALL export it. |  |
| AC-9 | test | WHEN a candidate scores [1.0, 0.0] on a case, `add_validation_scores` SHALL give 0.5 for that case, a stall window SHALL count the case only after both repeats are attempted, AND `criteria_flags` SHALL still report the level spread across the two outcomes. |  |
| AC-10 | test | WHEN the headroom pass scores the seed, THE SYSTEM SHALL record two outcomes per validation case, AND a seed with one repeat missing SHALL count that case as missing. |  |
| AC-11 | test | WHEN one repeat fails and one is scored, THE SYSTEM SHALL treat the case as complete with the scored value; WHEN both fail, the case SHALL be unscored; AND `validation_complete` SHALL be the only completion test that the Leaderboard, history, and stall readers call, so #245 can reuse it. |  |
