# gh-500: repeat validation runs and gate the incumbent with the 2-SE rule

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/500

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a candidate is scored on a validation case, THE SYSTEM SHALL record two outcomes with `repeat` 0 and 1 from two provider calls, AND GEPA SHALL receive their mean. |  |
| AC-2 | test | WHEN no token rule is set AND the incumbent scores [1.0, 0.5] and a challenger scores [0.9, 1.0] on each of four validation cases, THE SYSTEM SHALL keep the incumbent AND append a comparison with `verdict` `inconclusive`, `delta` 0.2, and `se` 0.1275. |  |
| AC-3 | test | WHEN no token rule is set AND the incumbent scores [0.5, 0.25] and a challenger scores [1.0, 0.75] on each of four cases, THE SYSTEM SHALL make the challenger the incumbent with `verdict` `promote`, `delta` 0.5, and `se` 0.0884; WHEN `min_gain` is 0.6, THE SYSTEM SHALL keep the incumbent. |  |
| AC-4 | test | WHEN `min_token_saving` is 0.1 AND `max_quality_loss` is 0.3 AND the incumbent and a challenger both score [1.0, 0.75] on each of four cases AND the paired mean task tokens per case are (1000, 600), (1000, 620), (1000, 580), (1000, 600), THE SYSTEM SHALL make the challenger the incumbent with `verdict` `promote-cheaper`, `delta` 0.0, and `se` 0.0884; WHEN no token rule is set, the same inputs SHALL keep the incumbent with `verdict` `inconclusive`. |  |
| AC-5 | test | WHEN the search is planned and run THE SYSTEM SHALL count `VALIDATION_REPEATS` per validation case in admission, `search_allowance` and its overshoot, and the `search_ceiling` seed term. Each seed validation pair reused from the baseline SHALL cost zero physical calls in search. Fresh search task runs SHALL NOT exceed the planned search share. |  |
| AC-6 | test | WHEN GEPA selects a parent, THE SYSTEM SHALL pass per-case mean scores and SHALL NOT filter candidates by the 2-SE rule. |  |
| AC-7 | test | WHEN the search stops, THE SYSTEM SHALL write `search.stop_trigger` with the limit that fired, tested once for each value: `metric-count`, `call-share`, `stall`, `search-deadline`, `deadline`, and `call-cap`. |  |
| AC-8 | test | WHEN a current-schema record has a different `validation_policy.repeats` or no `validation_policy` THE SYSTEM SHALL normally refuse resume before the engine-hash check. A complete current-schema record with no validation policy in either location and a different engine hash SHALL refuse resume but still export. The runner SHALL refuse to resume a record with an older run schema. |  |
| AC-9 | test | WHEN a candidate scores [1.0, 0.0] on a case, `add_validation_scores` SHALL give 0.5 for that case, a stall window SHALL count the case only after both repeats are attempted, AND `criteria_flags` SHALL still report the level spread across the two outcomes. |  |
| AC-10 | test | WHEN the baseline scores the seed THE SYSTEM SHALL record two outcomes per validation case. A case with one missing repeat SHALL count as missing. Resume SHALL score only the missing repeat. |  |
| AC-11 | test | WHEN one repeat fails and one is scored, THE SYSTEM SHALL treat the case as complete with the scored value; WHEN both fail, the case SHALL be unscored; AND `validation_complete` SHALL be the only completion test that the Leaderboard, history, and stall readers call, so #245 can reuse it. |  |
| AC-12 | test | WHEN a challenger has one validation case with no attempted repeat, THE SYSTEM SHALL record no comparison and keep the incumbent; WHEN its last repeat completes, THE SYSTEM SHALL record the comparison. |  |
