# gh-757: the search objective and the candidate floor

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/757

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a `--search` call names no `--objective` for a run directory whose `plan_mode` is `baseline` THE SYSTEM SHALL use the quality objective: a search with strict improvement, also when the contract sets `statistics.min_token_saving`; the `promote-cheaper` verdict of the gate SHALL stay keyed to the contract threshold |  |
| AC-2 | test | WHERE the user passes `--search --objective tokens` THE SYSTEM SHALL use the cheaper-tie acceptance and SHALL reflect on a perfect minibatch; IF the contract sets no `min_token_saving`, THEN THE SYSTEM SHALL stop with a usage error before any model call; IF a call gives `--objective` without `--search` for a run directory whose `plan_mode` is `baseline`, THEN THE SYSTEM SHALL stop with a usage error before any model call |  |
| AC-3 | test | WHERE the user passes `--search --objective tokens` and a train or validation family is at or above the headroom ceiling THE SYSTEM SHALL NOT stop with `cases-too-easy` and SHALL continue to the candidate floor of AC-6 |  |
| AC-4 | test | WHEN `run` is called on a run directory whose `plan_mode` is `search` and the call names no `--objective` THE SYSTEM SHALL use the recorded objective; IF the call names an objective that differs from the recorded one, THEN THE SYSTEM SHALL refuse the resume and make no model call |  |
| AC-5 | test | WHEN the system shows a search estimate THE SYSTEM SHALL include `expected_candidates` and the gate reserve |  |
| AC-6 | test | IF the search plan for the requested budget buys fewer than 6 candidates, THEN THE SYSTEM SHALL stop with `search-underpowered` before the search budget question and before any search call, whether or not the call gives `--approve-budget`; the stop data SHALL hold `expected_candidates` and the smallest budget that buys 6 candidates, or SHALL state that no budget up to the raised-cap limit buys 6; the baseline report SHALL stay in place |  |
| AC-7 | test | WHEN the user passes `--search` for a run directory that holds a baseline THE SYSTEM SHALL apply three steps in this order: the `cases-too-easy` check under the quality objective; the candidate floor of AC-6; then the stop with `budget-unapproved` and the search estimate |  |
| AC-8 | test | WHEN the search builds a reflection minibatch THE SYSTEM SHALL use 3 examples, and the plan estimate SHALL follow that size |  |
| AC-9 | process | The `autoimprove` procedure of the skill describes `--objective`, the `search-underpowered` stop, and the rule that the user repeats `--objective` until the search budget approval; it describes two passes in this order: a quality search, then, when the contract sets `min_token_saving`, a token search in a new run directory on the result of the first pass; the command of the token pass names no `--edit prose`; the `skillz-self-update` procedure describes the same two passes | review of `skills/skillz/references/autoimprove-run.md` and `.agents/skills/skillz-self-update/SKILL.md` |
| AC-10 | test | WHEN a `--search --objective tokens` call names no `--edit` THE SYSTEM SHALL plan `prose+cli` and SHALL record that edit mode for the run, and SHALL fall back to `prose` only under the fallback rules of today, with the reason in the output. This row locks the default of today for the new token path |  |
| AC-11 | test | WHERE the objective is tokens and the edit mode of the run is `prose`, by name or by fallback, THE SYSTEM SHALL put a warning in the search budget stop that says the search can edit Markdown only and names `--edit prose+cli` |  |
| AC-12 | test | WHEN a `--search` call uses the quality objective, the contract sets `statistics.min_token_saving`, and one train or validation family is at or above the headroom ceiling THE SYSTEM SHALL stop with `cases-too-easy` and SHALL make no search call. Today that contract field turns the stop off |  |
| AC-13 | test | WHEN a `--search` call gives the search budget approval THE SYSTEM SHALL store the objective of that call in `run.json` together with `plan_mode` `search`; the `--objective` of an earlier call that stopped SHALL NOT decide it |  |

The search metric of the plan was capped at 4 x (train + 2 x validation) calls, and intake splits the families evenly between train and validation, so no task run reached 6 candidates at any budget.
The maintainer decided on 2026-11-28 that the plan sizes the search for at least 6 candidates and lets the cap trim it, so that a budget buys candidates (pragmatic ADR-005 amendment).
