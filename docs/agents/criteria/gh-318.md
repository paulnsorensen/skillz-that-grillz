# gh-318: the Codex adapter retries a rate limit and keeps diagnostic text

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/318

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN a Codex call fails as `rate-limited`, THE SYSTEM SHALL retry it with exponential backoff, at most 3 times and only within the remaining time. |  |
| AC-2 | test | WHEN THE SYSTEM retries a call, THE SYSTEM SHALL count the retry in a `retries` field of the run record and summary, and SHALL NOT count it against the approved call budget. |  |
| AC-3 | test | WHEN Codex reports a retry-after or reset time, THE SYSTEM SHALL wait at least that long before the retry, and SHALL fail the call as `rate-limited` when the wait exceeds the remaining time. |  |
| AC-4 | test | THE SYSTEM SHALL keep a redacted stderr excerpt of at most 1 KiB and the error event messages in the failure evidence. |  |
| AC-5 | test | THE SYSTEM SHALL match a status code as a whole word, so `429` inside a port, path, or token count does not classify as `rate-limited`; the `login` and `connection` patterns SHALL match only failure phrases. |  |
| AC-6 | test | WHEN a rate limit occurs, THE SYSTEM SHALL halve the concurrent model calls for the rest of the run, to a minimum of 1. |  |
