## Shared fixture approval hashing

Shared fixture approval hashing streams canonical JSON into SHA256 without collecting repeated fixture text.[^1]
This preserves legacy approval digests, inline formats, and byte limits.[^2]
Regression tests check bounded allocation, legacy hashes, and case IDs in missing fixture errors.[^3]

## Shared seed byte bound

Shared fixture seed counting measures the written JSON, including indentation, its final newline, and UTF-8 encoding.[^4]
The whole document must fit `SEED_LIMIT`; shared fixture text still counts once.
Regression tests accept exactly the byte limit and reject one extra byte before writing a seed.[^5]
Legacy root-list drafts accept inline file maps and empty file lists, but not nonempty fixture references.[^6]
Shared-object drafts retain fixture references. Runtime validation remains authoritative for fixture lookup.[^7]
