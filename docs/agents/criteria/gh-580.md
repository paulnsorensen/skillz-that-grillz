## Shared fixture approval hashing

Shared fixture approval hashing streams canonical JSON into SHA256 without collecting repeated fixture text.[^1]
This preserves legacy approval digests, inline formats, and byte limits.[^2]
Regression tests check bounded allocation, legacy hashes, and case IDs in missing fixture errors.[^3]

## Shared seed byte bound

Shared fixture seed counting measures the written JSON, including indentation, its final newline, and UTF-8 encoding.[^4]
The whole document must fit `SEED_LIMIT`; shared fixture text still counts once.
Regression tests accept exactly the byte limit and reject one extra byte before writing a seed.[^5]
Legacy root-list drafts accept inline file maps and empty file lists, but not nonempty fixture references.[^6]
Shared-object drafts retain fixture references. Runtime validation remains authoritative for fixture lookup.[^7]

## Mixed fixture references

Shared fixtures handle conflicting paths independently. A case keeps a conflicting path inline without repeating other matching fixture contents.[^8]
A `files` map combines inline strings with `null` references into the top-level `fixtures` map.
Complete reference lists and inline maps remain valid. Legacy list drafts still require inline maps or empty lists.[^9]
Fixture maps contain strings only. Runtime validation rejects missing references, invalid values, unsafe paths, and runtime-owned paths.[^10]
Approval hashes still cover expanded contents. The seed and manifest bounds do not change.
The regression freezes twelve cases with a conflicting path and a matching 300000-byte file, then reloads exact contents.[^11]

## Shared fixture selection

A small first fixture must not force later large values inline.
Select each path's shared value before encoding references. Rank values by saved serialized JSON bytes, with a deterministic text tie-break.[^15]
Select across scored, pending, and unscored cases together. Preserve existing fixture bindings when a caller supplies them.[^16]
A 302986-byte draft with one small conflict and twelve large references freezes into 306214 bytes in either order.[^17]
This rule does not change approval hashes, legacy formats, or byte limits.

## Frozen manifest byte bound

Approved case freezing measures the exact written JSON, including indentation, escaped Unicode, and its final newline.[^12]
The complete manifest includes shared fixtures, scored cases, pending cases, and `not_scored` cases.
A manifest above 2000000 bytes stops with `cases-too-large` before creating or replacing `cases.json`.
Exactly 2000000 bytes remain valid; the loader retains the same bound.[^13]
Regression coverage checks the exact limit, one extra byte, escaped Unicode, and preservation of existing output.[^14]
