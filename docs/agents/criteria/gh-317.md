# gh-317: score the baseline on the holdout when the search retains the seed

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/317

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN the search retains the seed THE SYSTEM SHALL score the `baseline` arm on the holdout, and SHALL record `gate.baseline_scores` with one mean per scored holdout case. |  |
| AC-2 | test | WHEN the search retains the seed THE SYSTEM SHALL keep the verdict `inconclusive` with the reasons `["winner-equals-baseline"]`. |  |
| AC-3 | test | WHEN a budget or deadline stop leaves the baseline pass of a retained seed partly or fully unscored THE SYSTEM SHALL complete the run, keep any `gate.baseline_scores` (including the scores that a resume restored), and set `gate.baseline_skipped` to `budget-short`. |  |
| AC-4 | test | WHEN every baseline holdout evaluation of a retained seed faults THE SYSTEM SHALL complete the run with `gate.baseline_skipped` set to `faulted`. |  |
| AC-5 | test | WHEN baseline scores exist for a retained seed THE SYSTEM SHALL compute the `holdout-coverage` check from the baseline slots, and WHEN `baseline_skipped` is set or each missing baseline slot ends in a failed evaluation or a check timeout THE SYSTEM SHALL report it as `unknown`. |  |
