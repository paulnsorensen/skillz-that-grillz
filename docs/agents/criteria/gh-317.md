# gh-317: score the baseline on the holdout when the search retains the seed

Source: https://github.com/paulnsorensen/skillz-that-grillz/issues/317

| id | kind | criterion | verified by |
| --- | --- | --- | --- |
| AC-1 | test | WHEN the search retains the seed THE SYSTEM SHALL reuse its measured holdout scores and score only newly needed repeats. It SHALL record `gate.baseline_scores` with one mean per scored holdout case. |  |
| AC-2 | test | WHEN the search retains the seed THE SYSTEM SHALL keep the verdict `inconclusive` with the reasons `["winner-equals-baseline"]`. |  |
| AC-3 | test | WHEN a budget or deadline stops newly needed holdout repeats for a retained seed THE SYSTEM SHALL complete the run and keep `gate.baseline_scores`, including restored scores. It SHALL set `gate.baseline_skipped` to `budget-short`. |  |
| AC-4 | test | WHEN every newly needed holdout repeat for a retained seed faults THE SYSTEM SHALL keep the measured holdout scores and complete the run with reason `winner-equals-baseline`. |  |
| AC-5 | test | WHEN baseline scores exist for a retained seed THE SYSTEM SHALL compute the `holdout-coverage` check from the baseline slots, and WHEN `baseline_skipped` is set or each missing baseline slot ends in a failed evaluation or a check timeout THE SYSTEM SHALL report it as `unknown`. |  |
